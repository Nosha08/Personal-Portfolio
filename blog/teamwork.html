Building SammyGPT: Language Detection, RAG, and Serving Immigrant Families

Thousands of immigrant families on Staten Island can’t easily communicate with their children’s schools because of language barriers. Here’s how SammyGPT works under the hood to dissolve that barrier.

My high school, known for being “technical”, has a running joke about how bad our website is: awkwardly embedded animations, navigation overlaps, and sheer difficulty finding anything. I learned this the hard way, volunteering at my first open house, when a parent asked about our STEM programs. I pulled out my phone, searching our site frantically as their eager smiles faded into polite frustration.

That awkwardness stung. Our website was clearly inconvenient, but given school bureaucracy, I knew that redesigning it wasn’t an option. However, a former student’s project, SammyGPT, offered a starting point. I took ownership of the project with a new goal: transforming it from a prototype into a scalable tool. I retrained its models on verified school data to reduce hallucinations about nonexistent classes, then optimized multilingual processing to serve the 70% of families speaking another language at home.

After presenting the updated version to our administrators, I recognized a broader pattern: Staten Island had numerous schools with high immigrant populations and, surprisingly, even worse websites. I proposed expanding SammyGPT’s reach, turning it from a personal fix into a community resource, now capable of serving families borough-wide. Here’s how the backend actually works.

The Server: Flask + WebSockets

The backend is a Flask app using Socket.IO for real-time, word-by-word streaming — the same pattern that makes ChatGPT feel responsive. CORS is locked to three known origins so the API can’t be hit from arbitrary frontends. 

from flask import Flask, request, jsonify
from flask_socketio import SocketIO, emit
from flask_cors import CORS

app = Flask(env.name)
cors = CORS(app, origins=[
    "http://localhost:3000",
    "https://sammygpt.netlify.app",
    "https://sammy.siths.tech"
])
socketio = SocketIO(app, cors_allowed_origins=[
    "http://localhost:3000",
    "https://sammygpt.netlify.app",
    "https://sammy.siths.tech"
])

A global semaphore caps how many generations can run in parallel, preventing the server from being overwhelmed when multiple parents are querying at the same time: 

semaphore = threading.Semaphore(env.max_processes_at_a_time)

# Inside the generate handler:
with semaphore:
    # process the prompt

Language Detection and Translation

The core challenge is multilingual input. A parent might send a message in Spanish, Mandarin, or Haitian Creole. The pipeline detects the language, translates the prompt into English for retrieval, generates a response in English, then translates the response back to the parent’s language before sending it. 

current_language = "en"
default_language = "en"
same_as_default = False

if (env.enable_translate):
    current_language, confidence = Bot.translate_model.detect_language(prompt)

    if (current_language != default_language):
        # Word-by-word streaming not supported across languages —
        # translate the whole prompt first, then generate
        translated = Bot.translate_model.translate(
            prompt, current_language, default_language
        )
        prompt = translated.get("translated")
    else:
        same_as_default = True

When the language matches English, responses stream word-by-word in real time. For other languages, the full response is generated first, then translated in one pass — because token-by-token streaming doesn’t compose cleanly with translation.

Intent Classification: When Not to Retrieve

Not every question needs school documents. “What is photosynthesis?” doesn’t require pulling from a policy handbook. An intent classifier runs on every prompt before retrieval, and if it identifies a general question, the vector database step is skipped entirely: 

if (Bot.intent_model.classify(prompt)[0]['label'] == 'General Request'):
    need_reference = False

This keeps responses fast for general queries and avoids injecting irrelevant school documents into the context window.

Vector Retrieval: Grounding Answers in Real Documents

Each school’s policy documents and handbooks are embedded into a scoped vector store using semantic chunking. When a parent asks a school-specific question, the top matching passages are retrieved and injected into the prompt as context — preventing hallucination on school-specific facts. 

if (Bot.vectordb):
    db_result = Bot.vectordb.query(
        query_text=prompt,
        n_results=env.database_fetch_limit
    )

    for meta in db_result.get("metadatas")[0]:
        references.append(meta.get("link"))

    additional_info += Bot.vectordb.format_query(db_result)

Source links are tracked across both the vector database and the browse API so the frontend can show parents exactly where each answer came from.

Content Moderation

Before any response reaches a parent, it passes through a cleanse function that redacts blacklisted words. The list is loaded from a JSON file on every call so it can be updated without redeploying the server:
